# MCP 2026-07-28 Spec Digest (for offensive review)

Current revision: **2026-07-28**. Previous: **2025-11-25**. Older: 2025-06-18,
2025-03-26, 2024-11-05. Source of truth:
`https://modelcontextprotocol.io/specification/2026-07-28`.

Re-read this at the start of every review; pin the exact revision the target
implements. A review against the wrong era produces false negatives.

---

## Eras — determine which one you are testing

| Era | Revisions | Handshake |
|---|---|---|
| **Modern** | 2026-07-28 and later | None. Per-request `_meta`. |
| **Legacy** | 2025-11-25 and earlier | `initialize` + `notifications/initialized`. |

- Server capability probe is now **`server/discover`** (servers **MUST**
  implement it). It returns `supportedVersions`, `capabilities`, `serverInfo`,
  `instructions`.
- Detection: send a modern request. On `400`, inspect the body — a recognized
  modern JSON-RPC error (`UnsupportedProtocolVersionError`, etc.) means modern;
  anything else means fall back to `initialize` (legacy). Era is per-server, not
  per-request.
- **A repo that only shows `initialize` is legacy-era.** Flag the era in the
  verdict; legacy settings carry the removed attack surface below.

## Statelessness (the core change)

- **No protocol sessions.** `Mcp-Session-Id`, HTTP GET stream, `Last-Event-ID`
  resumability, and `DELETE` session teardown are **gone** from 2026-07-28.
- Every request carries required `_meta`:
  `io.modelcontextprotocol/protocolVersion` (required),
  `io.modelcontextprotocol/clientCapabilities` (required),
  `io.modelcontextprotocol/clientInfo` (SHOULD).
- Servers **MUST NOT** rely on prior requests for context; every request is
  self-contained.
- Cross-call state is via **explicit server-minted handles** passed as tool
  args (SEP-2567). A handle is a **name, not a capability** — authenticated
  servers **MUST** verify authorization on every call; unauthenticated servers
  where the handle is a bearer token **MUST** use sufficient entropy
  (e.g. UUIDv4) and a bounded lifetime.
- `serverInfo`/`clientInfo` are **self-reported and unverified**; clients
  **SHOULD NOT** rely on them for security decisions.

## Streamable HTTP wire format

- Single POST endpoint. Client sends each JSON-RPC message as its own POST;
  `Accept: application/json, text/event-stream`.
- **Required headers:** `MCP-Protocol-Version`, `Mcp-Method` (all requests),
  `Mcp-Name` (`tools/call`, `resources/read`, `prompts/get`). Header value
  **MUST** match the body; mismatch → `400` + `-32020 HeaderMismatch`. This is
  the source of the **proxy/body desync** class: intermediaries may route or
  rate-limit on the header while the server executes the body.
- `x-mcp-header`: a tool parameter annotated with `x-mcp-header: "<Name>"` is
  mirrored into an `Mcp-Param-<Name>` HTTP header. Constraints: non-empty; HTTP
  token syntax; no CR/LF; case-insensitively unique; primitive types only (not
  `number`); statically reachable via `properties` only. Values that are not
  header-safe are Base64 sentinel-encoded as `=?base64?<b64>?=`. Servers **MUST**
  validate header vs body (decoding sentinels first).
- `Origin` **MUST** be validated (403 on invalid) — DNS rebinding defence.
  Locally, bind `127.0.0.1`, not `0.0.0.0`.
- Error codes: `-32020 HeaderMismatch`, `-32021 MissingRequiredClientCapability`,
  `-32022 UnsupportedProtocolVersion`; `-32002` resource-not-found is legacy
  (now `-32602`).

## Result envelope

- Every result **MUST** carry `resultType`: `"complete"` or `"input_required"`
  (absent ⇒ treat as `complete`). Unknown `resultType` **MUST** be treated as
  invalid.

## MRTR (multi round-trip requests) — new in 2026-07-28

- Replaces server-initiated `roots/list` / `sampling/createMessage` /
  `elicitation/create`.
- Server returns `InputRequiredResult` with `inputRequests` (a map of
  `elicitation/create`, `sampling/createMessage`, `roots/list`) and an opaque
  `requestState`. The client retries the original request with `inputResponses`
  + `requestState`; the JSON-RPC `id` **MUST** differ between attempts.
- Only `prompts/get`, `resources/read`, `tools/call` support MRTR.
- **`requestState` is attacker-controlled.** Servers **MUST** treat it as such;
  if it affects authorization they **MUST** protect its integrity (HMAC/AEAD)
  and reject anything that fails verification, and **SHOULD** bind it to the
  authenticated principal, a TTL, and the originating request.

## Subscriptions

- `subscriptions/listen` (replaces `resources/subscribe` and the GET stream).
  Opt-in filters: `toolsListChanged`, `promptsListChanged`,
  `resourcesListChanged`, `resourceSubscriptions`.
- Server **MUST NOT** send notification types not explicitly requested; first
  message is `notifications/subscriptions/acknowledged`; every message carries
  `io.modelcontextprotocol/subscriptionId` in `_meta`.
- Consequence: the tool/resource set can mutate **mid-session** — the rug-pull
  now happens on a live stream, not only across restarts.

## Caching

- Results may carry `ttlMs` and `cacheScope` (`public` | `private`).
- Retries carrying `inputResponses`/`requestState` **MUST NOT** be cached.
- Caches **MUST NOT** be shared across authorization contexts; servers **MUST
  NOT** rely on `cacheScope` alone to prevent unauthorized access.

## Pagination

- `cursor`/`nextCursor` are opaque. Clients **MUST** treat them as opaque; an
  invalid cursor returns `-32602`. No cross-page consistency guarantee.

## Tools

- `inputSchema`/`outputSchema` are **JSON Schema 2020-12** by default;
  `$ref` to a network URI **MUST NOT** be auto-dereferenced (schema SSRF).
  Composition keywords can DoS a naive validator.
- **Tool annotations are untrusted** — "clients **MUST** consider tool
  annotations to be untrusted unless they come from trusted servers."
- Tool names: 1–128 chars, ASCII letters/digits/`_ - .`; unique per server.
  Clients/proxies aggregating multiple servers **MAY** hit collisions and
  **SHOULD** prefix by server id.
- `icons[]`: client may fetch `src`; spec requires HTTPS or `data:` only,
  same-origin, no credentials, magic-byte validation, and treats SVG as
  executable-capable.

## Resources / prompts / discovery / logging

- Resources: `file://` paths **MUST** be sanitized for traversal; custom
  schemes and `https://` resources can cause the client itself to fetch.
- Prompts: prompt content is a **prompt-injection** vector; inputs/outputs
  **MUST** be validated.
- `server/discover`: `instructions` is untrusted text fed toward the model —
  an injection vector.
- Logging (**deprecated**, SEP-2577): per-request `_meta`
  `io.modelcontextprotocol/logLevel`; servers **MUST NOT** emit
  `notifications/message` for a request lacking it; logs **MUST NOT** contain
  credentials, secrets, PII, or internal system details.

## Authorization (HTTP)

- OAuth 2.1; PKCE with `S256` **MUST** be implemented and verified.
- **Token passthrough is forbidden:** "MCP servers **MUST NOT** accept any
  tokens that were not explicitly issued for the MCP server" — and **MUST NOT**
  forward the client's token to upstream APIs. Audience validation is mandatory.
- Resource Indicators (RFC 8707): client **MUST** include `resource` in both the
  authorization and token requests. Protected Resource Metadata (RFC 9728) is
  mandatory for servers.
- `iss` (RFC 9207): clients **MUST** validate a present `iss` against the
  recorded issuer before redeeming; no normalization.
- Client registration: pre-registered → **CIMD** (URL client-id metadata
  document, SEP-991, `SHOULD`) → **DCR** (deprecated; requires
  `application_type`). Credentials **MUST** be keyed by `issuer` and **MUST NOT**
  be reused across authorization servers.
- Confused deputy: proxies **MUST** implement per-client consent, exact-match
  redirect URIs, cryptographically random single-use server-side `state`, and
  `__Host-` consent cookies not set before consent. Framing blocked.
- SSRF: block private/reserved IP ranges; HTTPS; validate redirect targets.
- Clients **MUST NOT** open authorization URLs via a shell; **MUST** reject
  `javascript:`/`data:`/`file:`/`vbscript:`.

## Local server installation

- Clients that install/launch local servers with one click **MUST** obtain
  consent showing the **exact untruncated command** before executing, and
  **SHOULD** sandbox. stdio: newline-delimited JSON-RPC; the server **MUST NOT**
  write anything to stdout that is not a valid MCP message, and **MUST NOT**
  write JSON-RPC requests to stdout.
- Roots are **informational only** — the protocol does not enforce that a server
  stays in bounds; clients **MUST** validate root URIs.

## Deprecated (plan for removal ≥ 2027-07-28)

Roots, Sampling, Logging (SEP-2577); OAuth DCR (RFC 7591); HTTP+SSE transport
(2024-11-05); `includeContext: thisServer|allServers`.

## Extensions (separate specs — review when the server claims them)

- **MCP Apps**: server provides interactive HTML via a `ui://` resource
  referenced by `_meta.ui.resourceUri`; rendered in a host-controlled sandboxed
  iframe using `postMessage`; `_meta.ui.csp`/`permissions` govern external
  loads and capabilities. New client-side surface (HTML/JS in the host, CSP,
  tool-call proxying from the app).
- **Tasks** (async work), **Skills over MCP** (server-hosted Agent Skills),
  **Enterprise-Managed Authorization** (IdP-controlled), **OAuth client
  credentials** (M2M).

## Registry & supply chain

- Official MCP Registry is metadata-only (`server.json`), namespace-authenticated
  by DNS/GitHub/HTTP proof. It **delegates vulnerability scanning** to npm/PyPI/
  Docker and downstream aggregators. Publishing metadata ≠ vetted code; treat
  registry presence as provenance signal only, never as a security pass.

## Security Best Practices (named vectors to test)

Confused deputy · token passthrough · SSRF · **state-handle hijacking** ·
local MCP server compromise (one-click install) · OAuth URL validation
(shell/XSS) · mix-up attack (PKCE alone does not prevent it) · localhost redirect
URI impersonation · scope creep · CIMD trust policy · elicitation phishing via
URL mode.
